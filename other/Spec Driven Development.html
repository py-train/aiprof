The Problem with "Vibe Coding"

Why AI Agents Need Structure

  • Context Loss: AI forgets what you asked for
  • Drift: Implementation diverges from intent
  • Rework: Built wrong, rebuild from scratch

What is Spec-Driven Development?

Executable specifications become the single source of truth that AI agents convert into working code, tests, and documentation.

Clear specs → Better AI output → Fewer iterations

The SDD Workflow

1. Specification

Clear requirements, acceptance criteria, data models

2. Planning

Technical design, architecture, dependencies

3. Tasks

Phased implementation steps

Why Spec-Driven Development Works

  • Clarity: AI knows what to build and why
  • Traceability: Code links back to requirements
  • Quality: Fewer bugs from misunderstanding
  • Docs: Specs stay current with code

Phase 1: Specification

What to Include

  • User stories with acceptance criteria
  • API contracts and data schemas
  • Edge cases and constraints
  • Non-functional requirements (perf, security)

Good Spec vs Bad Spec

❌ Bad Spec

"Build a user auth system"

✅ Good Spec

"JWT-based auth with email/password, OAuth (Google), 2FA optional, session timeout 24h"

Phase 2: Technical Planning

Architecture & Design Decisions

  • Tech stack selection (frameworks, libraries)
  • Database schema and relationships
  • Service boundaries and APIs
  • Deployment and infrastructure

Phase 3: Task Breakdown

Implementable Chunks

  • Break plan into ordered, testable tasks
  • Each task links to spec requirements
  • Clear success criteria per task
  • AI can implement tasks autonomously

Introducing Kiro

Kiro Spec Mode Workflow

  • 1. Requirements: Describe feature in natural language
  • 2. Design Doc: Kiro generates high-level design
  • 3. Review: Refine specs with AI assistance
  • 4. Implement: Kiro generates code from specs

Kiro: Writing Requirements

User Story:
As a user, I want to upload files and have them chunked 
automatically so I can process large files efficiently.

Acceptance Criteria:
- Support file upload via drag-and-drop
- Chunk files into 5MB segments
- Display progress bar during processing
- Generate downloadable chunks as .zip
- Handle errors gracefully with user feedback

Kiro converts this into structured design doc

Kiro: Generated Design Doc

## Architecture
- Frontend: React with drag-and-drop library
- Backend: Node.js Express API
- Storage: S3 for temporary file storage

## Components
1. FileUploader (React component)
2. ChunkingService (backend service)
3. ProgressTracker (WebSocket for real-time updates)

## Implementation Plan
Phase 1: Frontend upload UI
Phase 2: Backend chunking logic
Phase 3: Progress tracking & download

Kiro: Iterative Spec Refinement

Chat with Kiro to clarify and refine specs

  • "What if user uploads non-text files?"
  • "Should we support custom chunk sizes?"
  • "How to handle network failures mid-upload?"

Kiro: From Spec to Code

Implementation Phase

  • Kiro generates complete components
  • Writes unit tests automatically
  • Runs tests in live browser (Playwright)
  • Fixes bugs based on test failures

Kiro Best Practices

  • Be Specific: Detailed specs = better code
  • Iterate on Specs: Refine before coding
  • Use Examples: Show what "good" looks like
  • Review Output: Verify generated code

VS Code Spec Kit

Open Source SDD Toolkit for Any AI Assistant

What is Spec Kit?

  • GitHub Project: Open source SDD toolkit
  • VS Code Extension: SpecKit Companion
  • AI-Agnostic: Works with Copilot, Cursor, Cody
  • Slash Commands: /specify, /plan, /tasks

Spec Kit Workflow

/specify

Create specification document

/plan

Generate technical plan

/tasks

Break into implementation tasks

Spec Kit: /specify Command

You: /specify
Build a file upload and chunking utility

AI generates spec.md:
# File Chunking Utility

## Overview
Web-based tool for splitting large files into chunks

## Requirements
- Drag-and-drop upload interface
- Configurable chunk size (1MB-10MB)
- Progress visualization
- Download chunks as .zip

## Constraints
- Max file size: 100MB
- Browser-based (no server upload)

Spec Kit: /plan Command

You: /plan

AI generates plan.md from spec.md:
# Technical Plan

## Architecture
- SPA: React + TypeScript
- File handling: FileReader API
- Chunking: Blob.slice()
- Compression: JSZip library

## File Structure
src/
  components/
    FileUploader.tsx
    ChunkProgress.tsx
  utils/
    chunker.ts
    zipper.ts

Spec Kit: /tasks Command

You: /tasks

AI generates tasks.md:
# Implementation Tasks

## Phase 1: Setup
- [ ] Initialize React + TypeScript project
- [ ] Install dependencies (JSZip)

## Phase 2: Upload UI
- [ ] Create FileUploader component
- [ ] Implement drag-and-drop

## Phase 3: Chunking
- [ ] Implement chunker utility
- [ ] Add progress tracking

## Phase 4: Download
- [ ] Implement zip generation
