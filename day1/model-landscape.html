The key split

The most important split in the landscape

Closed (proprietary)

  • • Model weights are private; you access via API or product
  • • Provider controls updates, pricing, and uptime
  • Examples: GPT-4o, Claude, Gemini

Open (open-weights)

  • • Weights are downloadable; you can run them yourself
  • • No per-token cost; you control the deployment
  • Examples: Llama 3, Mistral, Phi-3, Falcon

→ See the trade-off matrix on the next slide

For most enterprise use cases today: start closed, evaluate open for scale or privacy-sensitive workloads.

Decision guide

Four questions to guide model selection

Question 1

What's the task?

Reasoning-heavy? Use a strong frontier model. Simple extraction? A smaller, cheaper model works fine.

Question 2

Where does the data go?

If the content is confidential, check the provider's data-handling terms — or use an open model on-prem.

Question 3

What's the cost profile?

High-volume, repetitive tasks → optimize for price-per-token. Low-volume, high-stakes → pay for the best.

Question 4

What's the integration path?

Already in Azure/AWS/GCP? Use their offerings. Building standalone? Direct API is simpler.

You rarely pick a model forever. Run evals, compare, and revisit as capabilities change.

Within a provider

Not all models from one provider are the same

Standard models

e.g. GPT-4o, Claude 3.5 Sonnet

  • • Fast, cheap, excellent at most tasks
  • • Best default choice

Reasoning models

e.g. o1, o3, Claude extended thinking

  • • Spend extra compute "thinking before answering"
  • • Better at multi-step logic and math
  • • Slower and more expensive — use when you need it

Small / efficient models

e.g. GPT-4o-mini, Claude Haiku, Phi-3

  • • Lower cost, fast latency
  • • Classification, summarization, high-volume pipelines

Rule of thumb: use the smallest model that solves the problem reliably.

Optional depth · Context windows

How much a model can "see" at once

The context window is the total text a model can process in one interaction — your prompt, its previous responses, and any attached documents all count toward the limit.

Why it matters

  • • Longer context → paste in full documents and large datasets
  • • Larger context ≠ better attention — models can lose focus in the middle of very long inputs
  • • Cost scales with tokens; long contexts cost more

Optional depth · Benchmarks

Leaderboards tell you something — not everything

Common benchmarks you'll see cited:

  • MMLU — broad knowledge across 57 subjects
  • HumanEval — coding ability
  • MATH — mathematical reasoning
  • MT-Bench — multi-turn chat quality
  • LMSYS Chatbot Arena — human preference voting (most real-world signal)

The limitations

  • • Benchmarks measure narrow, standardized tasks — not your specific use case
  • • Models can be fine-tuned to score well on benchmarks without being genuinely better ("Goodhart's Law")
  • • The best benchmark is: does it do what I need, reliably?
Test on representative examples from your own domain before committing to a model.

Takeaway

What to remember

Default to a frontier model for most tasks

GPT-4o, Claude, Gemini — capability differences at this tier matter less than how well you prompt them.

Check data handling before using confidential content

Know whether your input is used for training, stored, or processed by a third party.

The landscape shifts fast

A model that's best today may not be in six months. Build habits around evaluating and comparing, not loyalty to a single tool.
